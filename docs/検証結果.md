# 検証結果（2026-09-21）

本開発に入る前に、「同じ Story が日をまたいで続きとして書けるか」だけを検証した。UI も OAuth 画面もまだない。このドキュメントが、zaru-note セッションから独立して再開するときの正本である。

## プロダクトの前提

- 名前は chobitnews。自分専用の GitHub 朝刊
- リポジトリは `~/Sites/chobitnews`。GitHub は `chobitapp/chobitnews`（旧 `zaru/chobitnews` から移管）。zaru-note には置かないし、依存もしない
- ローカルのプロジェクト配置は不定なので、入力は GitHub OAuth（検証では `gh auth` の user token で代用）
- 号は毎日閉じてよい。地続きになる単位は Edition ではなく Story。調査（Investigation）と判断（Judgment）を DB に残し、翌朝の入力にする
- 欲しい面はあとで足す。依存の最新、盛り上がっている議論、停滞と乗り換え、近傍 OSS、使い方の具体指摘。検証スパイクは世代割れ（drift）だけ

Contents read は広く配るには重いが、専用なので許容する。マニフェスト以外のソースは DB に積まない。

## 検証したこと

1. ローカルパスなしで、GitHub 上の `package.json` から直接依存が取れる
2. Investigation / Judgment / Story が SQLite に残る
3. 1日目: 世代割れを新規掲載する
4. 2日目: 入力が同じなら号の item は 0。Story は developing のまま。judgment は hold
5. 3日目: バージョンが揃ったら resolve し、解消だけ書く

コードの中心は `src/pipeline.ts`。テストは `test/continuity.test.ts`。GitHub 取得は `src/github.ts`。

## 手順

```sh
pnpm install
pnpm verify          # fixture の三日
pnpm verify:github   # 実 GitHub + 同じ三日のシミュレート
```

`verify:github` の3日目はリモートを書き換えない。世代割れの先頭パッケージをメモリ上で揃える。

## 結論

連続は成立している。手帳がなければ 2 日目はまた 8 本の「新ニュース」になる。号を増やす前に、Story を主語にする判断は本開発に残す。

## Beat（入力リポジトリ）

COLLABORATOR まで取ると会社 org の巨大 `package.json` が入り、朝刊にならない。切り方を実データで比較し、次でいったん固定した。パイプラインにはまだ入っていない。

- 個人: owner が `zaru` または `chobitapp`、かつ直近 90 日に push
- それ以外: デフォルトブランチの直近 30 日コミットで、viewer の割合が 30% 以上
- 貢献グラフ（`contributionsCollection`）は private org を隠すので使わない。リポジトリごとの `history(author: viewer)` で数える

この切りで root `package.json` を名寄せすると unique は約 107。増分のほぼ全部が `GVATECH-CTOROOM/AI-EDITOR`（自分 47 / 全体 103）。`basic-id` はコミット最多だが root マニフェストが無い。件数（自分 ≥5）にすると OLGA-DB が残り 175 まで広がるので、件数ではなく割合にする。

## 本開発へ持ち越す制約

- cinema-ticketing と Durable Objects デモは、直近 100 件のルート `package.json` に出ていない。GitHub に無い、ネストしている、または push が古い。OAuth してもローカル専用リポジトリは見えない
- 追跡パッケージを平等に扱うと biome / typescript / react が毎回一面になる。dotenv を外しただけでは足りない。Beat はリポジトリ集合まで決めた。紙面は手元の版を見ない（後述）
- OAuth アプリは未接続。検証の token は `gh auth` の代用
- Issue の熱、停滞、近傍、使い方指摘は未実装
- 号の Web / メールは未実装
- SQLite のスキーマはスパイク用。本開発で migration を正式化する

## 紙面の品質検証

いまの drift 号は興味を検証できない。連続（再掲載しない）と品質（読みたい）は別軸。

- Beat は「どのライブラリの上流を読むか」の名簿だけ

- TypeScript 7 のような大きいが古い発表は、今日の号にしない

## 段階検証 1: 固定世界からの OSS 収集（2026-09-21）

OAuth 画面と Beat 再発見を後回しにし、認可済みユーザと対象リポを `fixtures/world.json` に固定した。収集はそこから機械的に OSS を取り、共有カタログへ保存する。

- ユーザ `zaru`（github_id `235650`）。OAuth 行あり。token は fixture 文字列で、GitHub には使わない
- Beat は個人 org（`zaru` / `chobitapp`）かつ 90 日 push の 10 リポ。このプロダクト自身は `chobitapp/chobitnews`。root `package.json` があるのは 8。`zaru/note` と `chobitapp/chobitmail-skills` はマニフェスト無し
- 名簿は deny 後 37 unique。`@types/*` / `postcss` / `autoprefixer` は入らない
- 本番スキーマは `migrations/0001_catalog.sql`。`users` と `packages` は多対多（`user_packages`）。Releases / Advisories は OSS 側にだけ置く
- スパイクの drift 表（`src/schema.sql`）は連続テスト用に残し、本番 0001 には載せない


`data/catalog.sqlite` は再実行してよい。未適用 migration だけ流す。
